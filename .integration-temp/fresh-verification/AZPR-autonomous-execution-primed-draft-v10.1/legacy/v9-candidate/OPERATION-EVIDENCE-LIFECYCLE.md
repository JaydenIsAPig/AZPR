# AZPR v8 Operation–Evidence Lifecycle

V8 does not authorize any external operation. Existing exact operation registration, nonce binding, content-addressed create-once evidence, transactional attachment, status enforcement, signed indexes and audit-envelope controls are retained.

Before any future adapter may run, its exact installation manifest, executable/library identity, operation set, target attestation, execution mode, idempotency key, I/O limits, rollback semantics and isolated qualification evidence must be pinned in the trusted installation and installation authorization.

No production/customer target or credential was used during v8 development.
