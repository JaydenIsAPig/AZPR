# Runbooks

No operational product behavior is implemented, so no operational runbook currently exists.

When operational behavior is added, create concise runbooks for source failure/staleness, ingestion replay, low-confidence review, notification delivery failure, security/privacy incidents, backup/restore, and other relevant recovery paths. Every runbook must state owner, prerequisites, detection signal, safe procedure, verification, rollback/escalation, and last-tested date. Planned runbooks must be labeled planned and must not claim that tooling exists.
