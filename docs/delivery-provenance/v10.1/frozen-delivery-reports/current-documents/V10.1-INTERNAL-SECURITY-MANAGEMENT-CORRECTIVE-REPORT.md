# AZPR v10.1 Internal Security Management Corrective Report

The frozen source baseline was `AZPR-autonomous-execution-primed-draft-v10.zip`, SHA-256 `3e748b2e8e61033c741f138dae4357d60f020c7db15489333be73bed329741af`. ## Assessment findings addressed

The corrective iteration treated `AZPR-V10-IND-F01` through `AZPR-V10-IND-F06` as open until an enforcing source path and release-blocking regression rejected the independently observed behavior. `AZPR-V10-IND-F07` remains an honest operational gate.

### F01 — independent higher-level qualification authority

The qualification request no longer selects the trust-root location, expected owner, sequence floor, external signer executable, signer identity, or receipt-verification key. The public loader resolves a fixed host-root location and verifies a separately signed host-root manifest, fixed signer identity, receipt key, attestor authority, service executable, and signed remote-head response. A complete caller-created hierarchy is rejected by the input contract before receipt construction.

### F02 — exact signed policy semantics

The approved policy is parsed into an immutable authority object. Exact target membership, boundary values, observation names, and maximum envelope age are consumed by envelope verification. A policy requiring `DENY_ALL` rejects controlled-network mode; a one-second maximum-age policy rejects a one-hour-old envelope.

### F03 — attestation and actual executable identity

The probe-service attestation now requires an independently pinned attestor keyring, role, validity, and revocation state. It binds host, candidate, challenge, service identity, launcher, runtime configuration, and actual executable digest. The verifier hashes descriptor-opened executable bytes and rejects forged attestations or digest mismatch.

### F04 — complete release oracle

The release catalog is generated from collection and contains all 120 collected tests. Catalog/collection equality is a release invariant. Every test is executed separately with a hard deadline, bounded output, a clean environment, and process-group cleanup. The previously omitted inherited strict-schema-bounds oracle and all v10 independent reproductions are release blocking.

### F05 — bounded schemas

All ten independently reported unbounded locations now have explicit item, string, object-shape, enum/const, and aggregate constraints. The inherited global bounded-and-strict schema oracle passes.

### F06 — chronology and monotonic state

Trust, revocation, attestation, signer identity, and anchor records enforce issuance chronology and clock-skew limits. Sequence/order checks prevent stale local state. A fixed, independently signed anchor-client contract verifies the exact host-root manifest hash and sequence against a remote head; future-issued records and rolled-back sequence heads fail closed.

## Lingering concerns and non-paper gates

The following remain unproven and cannot be closed in this source-development environment:

- production HSM/external signer and real rollback-resistant remote anchor availability, custody, durability, and outage behavior;
- dedicated host kernel, filesystem, cgroups, namespaces, mounts, UID/GID, LSM, quota, and exact Codex runtime qualification;
- power loss, reboot, `kill -9`, disk/inode exhaustion, read-only remount, concurrent recovery, and anchor outage on the target host;
- supply-chain mirror, reproducible rebuild, SBOM, provenance, image, registry, and dependency-custody evidence;
- real key generation, custody, rotation, revocation, emergency disablement, and recovery ceremonies;
- canonical policy approval, manual Prompt 004, roadmap generation and independent promotion;
- actual AZPR repository, municipal sources, providers, customer isolation, consent/suppression, migrations, backup/restore, PII, and rollback qualification.

No positive production conclusion is inferred from source tests. A separate independent assessor must reproduce the caller-created hierarchy, policy-semantic, attestation, executable, chronology, schema, full-catalog, source-tree, and fresh-extraction checks against the final frozen bytes.

## Least-privilege verifier correction discovered during freeze

The first final UID 1000 read-only verifier run rejected release test `V10.1-REL-016` because the non-production reference anchor's explicitly test-owned storage path was not forwarded into the sanitized child environment. Root-only test execution had hidden the fallback to a shared `/tmp` path. The correction forwards `AZPR_REFERENCE_ANCHOR_ROOT` only to the exact bundled `file_anchor_reference.py` helper and only when production mode is false; production anchor execution remains fixed and sanitized. The failed first freeze attempt is retained as evidence and is not counted as a passing release verification.

The second final UID 1000 attempt exposed an inherited fixture that relied on the invoking account's umask. Under the reviewer account, group-writable fixture trust documents were correctly rejected before the intended rollback-evidence oracle. The fixture now assigns explicit restrictive modes to every trust document. This changes only test construction; the external runner's writable-path rejection remains intact.

The third UID 1000 attempt reached an inherited installer test that explicitly created its fixture under `/root`. It has been converted to consume a shipped immutable root-owned bundle and to simulate the prohibited writable mode at the exact `lstat` enforcement point. The installer still requires UID 0 ownership and rejects writable content; only the privilege-dependent fixture construction was removed.

A proactive scan found four additional historical `/root` fixtures and two skip-on-nonroot tests. They were not removed from the catalog. Non-root branches now execute the source-level enforcement oracles without claiming real UID-transition qualification; the original privileged branches remain available for the later dedicated-host matrix. This preserves the separation between reproducible source reassessment and operational root/host qualification.

The full UID 1000 catalog next reached activation recovery and correctly failed on the fixture's attempted root ownership change. The test now asserts the exact root-ownership call while continuing to execute the transaction and recovery path. This is a privilege-adaptation of the unit fixture, not a removal of the installer ownership requirement.

The remaining late-suite v7 completeness test also invoked a retired root-only verifier. Its non-root branch now exercises the full expected-set, unknown-entry, missing-entry, and path-alias logic without bypassing those oracles. The root requirement remains in the historical verifier and is not represented as operationally qualified.

The late-suite black-box harness exposed three cases that attempted `setgroups` and UID/GID transition from UID 1000. A narrowly gated self-identity test path now allows the process containment oracles to execute under the reviewer while preserving the exact privileged transition path for dedicated-host qualification. This does not prove non-root-agent separation on the target host; that remains an operational gate.

The late v9 signer regression used `/root` solely to obtain non-writable ancestors. Under the non-root reviewer it now uses `/home/oai`, whose ancestor chain satisfies the same no-group/no-world-write condition. This preserves the exact signer-client path oracle without requiring root.
